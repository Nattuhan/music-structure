# さよならベルのクリック補正（2026-09-09）

対象は `XUSMX3kEYoY-clip-0-228000`。他の曲や別の切り出し範囲へ自動適用しない。

## 原因と補正範囲

保存された最初の拍が1.83秒で、冒頭の4拍が欠落していた。既存の冒頭32拍は約0.387秒間隔で安定している。1.83秒の小節頭から0.3867秒ずつ逆算し、0.283、0.670、1.057、1.443秒を追加する。再生開始前のプリカウントを追加する変更ではない。

127.23〜139.59秒では、検出器が拍間隔を約0.39秒から約0.44秒へ伸ばしていた。ローカルWAVの5ms窓のRMS立ち上がりを確認すると、強いアタックは次の位置にある。

| アタック（秒） | 127.23秒からの概算拍位置 |
| --- | --- |
| 127.232 | 0 |
| 128.599 | 3.5 |
| 130.305 | 8 |
| 131.657 | 11.5 |
| 133.443 | 16 |
| 134.760 | 19.5 |
| 136.521 | 24 |
| 137.888 | 27.5 |
| 139.594 | 32 |

これは3.5拍・4.5拍の交互のアクセントで、テンポ変更ではない。表拍の127.23、130.30、133.44、136.52、139.59秒を8拍ずつ結ぶ。前後の拍は移動しない。小節頭とセクションの小節番号も更新する。

検出器全体に「短いテンポ変更は平坦化する」という推測は加えない。音源で確認したアンカーを明示的な補正レシピとして保存し、同一セッションの再解析時には保持する。

## 適用

`scripts/repair_timing.py --root <ローカル保存先> --recipe scripts/timing-corrections/XUSMX3kEYoY-clip-0-228000.json`

この処理はローカルの対象セッションとそのライブラリ表示だけを更新する。元結果を `.json.before-timing-repair` に保持し、再実行してもバックアップを上書きしない。ネットワーク同期、UI配信、音声の再生成は行わない。

## ループ再生の調査

再生処理は未変更。ブラウザの実メディア再生で0.75倍速、全曲ループと区間ループを各5周実行する回帰テストを追加した。各クリック予約をメディアの拍位置へ換算し、誤差30ms未満・シーク中の予約なしを確認した。

このテストは2秒の合成音源を使う。利用者の実機・実音源・パート音源併用時の可聴ずれを否定するものではない。報告されたループ中のずれそのものは未再現であり、シークを原因と断定しない。再現できた場合に、その条件と音声時刻の記録を基に別途修正する。
